# Jaga: Data Contract

Everything in the project connects through **Firebase Firestore**. The ESP32 writes, the web app reads, and the Cloud Function writes AI summaries. This file is the single source of truth for names and formats. If you need to change something, change it here first and tell the team.

**Status:** DRAFT. Each member confirms below, then it is frozen.

## Rules for everyone

- Collection and field names are **lowercase** and spelled exactly as written here.
- All times are stored as Firestore **timestamps** in UTC. The web app converts them to Malaysia time (UTC+8) for display.
- Button `type` values are exactly: `toilet`, `eating`, `pain`, `general`.
- LDR slot document IDs are exactly: `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`.
- The device is called `jaga-01`.

---

## Collection 1: `events`

One new document for **every button press**. Written by the ESP32. Read by the web app and the Cloud Function.

| Field | Type | Example | Meaning |
|---|---|---|---|
| `type` | string | `"pain"` | `toilet`, `eating`, `pain` or `general` |
| `ts` | timestamp | `2026-10-12T08:15:30Z` | when the button was pressed |
| `device` | string | `"jaga-01"` | which device sent it |

Document ID: auto-generated by Firestore.

Example document:

```json
{
  "type": "pain",
  "ts": "2026-10-12T08:15:30Z",
  "device": "jaga-01"
}
```

---

## Collection 2: `meds`

One document **per tray slot**, with the document ID equal to the day. Written by the ESP32 whenever a slot is opened. Read by the web app.

| Field | Type | Example | Meaning |
|---|---|---|---|
| `opened` | boolean | `true` | `true` once the slot has been opened |
| `ts` | timestamp | `2026-10-12T08:20:00Z` | last time the slot changed |

Document IDs: `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`.

Proposed rules (confirm as a team):
- A slot counts as **taken** only if `opened` is `true` and `ts` falls within the **current week**, so last week's data is not shown as this week's.
- The ESP32 **updates** the existing document. It does not create a new one each time.

Example document `meds/mon`:

```json
{
  "opened": true,
  "ts": "2026-10-12T08:20:00Z"
}
```

---

## Collection 3: `insights`

One new document for **every AI summary**. Written by the Cloud Function. Read by the web app (it shows the newest one).

| Field | Type | Example | Meaning |
|---|---|---|---|
| `createdAt` | timestamp | `2026-10-12T14:00:00Z` | when the summary was made |
| `text_en` | string | `"3 pain alerts this week, up from 1 last week..."` | English summary |
| `text_ms` | string | `"3 amaran sakit minggu ini, naik daripada 1..."` | Bahasa Melayu summary |
| `stats` | map (optional) | `{toilet: 6, eating: 4, pain: 3, general: 2}` | counts used for the chart |

Document ID: auto-generated by Firestore.

Wording rule for the AI text: describe **patterns only**. Do not diagnose. Suggest the caregiver discuss changes with a doctor.

## How each part reads and writes

| Part | Writes | Reads |
|---|---|---|
| ESP32 (`firmware/`) | `events` (create), `meds` (update) | nothing |
| Web app (`frontend/`) | nothing (except the hidden "Simulate event" button, which creates `events`) | `events`, `meds`, `insights` |
| Cloud Function (`functions/`) | `insights` (create) | `events` (last 7 days) |

## ESP32 request formats (Firestore REST API)

Replace `PROJECT_ID` and `WEB_API_KEY` with the values from the Firebase project settings (the `firebaseConfig` block).

**New button press** (HTTP POST):

```
POST https://firestore.googleapis.com/v1/projects/PROJECT_ID/databases/(default)/documents/events?key=WEB_API_KEY
Content-Type: application/json

{
  "fields": {
    "type":   { "stringValue": "pain" },
    "ts":     { "timestampValue": "2026-10-12T08:15:30Z" },
    "device": { "stringValue": "jaga-01" }
  }
}
```

**Slot opened** (HTTP PATCH, updates `meds/mon`):

```
PATCH https://firestore.googleapis.com/v1/projects/PROJECT_ID/databases/(default)/documents/meds/mon?updateMask.fieldPaths=opened&updateMask.fieldPaths=ts&key=WEB_API_KEY
Content-Type: application/json

{
  "fields": {
    "opened": { "booleanValue": true },
    "ts":     { "timestampValue": "2026-10-12T08:20:00Z" }
  }
}
```

The ESP32 needs the correct time (NTP) to build the `ts` value. Send it in UTC, formatted like `2026-10-12T08:15:30Z`.
